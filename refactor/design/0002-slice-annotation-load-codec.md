Status: proposed (maintainer to confirm; see [Q15](../QUESTIONS.md#q15))

First slice of [ADR 0001](0001-strangler-migration.md), the pilot of [PLAN](../PLAN.md) Phase 3.

## 2. Impurities found, and how the move keeps behavior

| Impurity | Where | Handling in the move (behavior-preserving) |
|---|---|---|
| global `hasLabel` (`SelectionControl.js:855`), mutates `obs.labels` | `sanitizeEvents` | injected as `deps.hasLabel`; the bridge passes the global |
| `alert` on duplicates | `sanitizeEvents` | injected as `deps.alert`; same text, same moment |
| `console.log`, global `logging.io` | all | `deps.log`, `deps.logIO` (bridge passes `console.log` and `logging.io`) |
| implicit globals `data0`, `hasDuplicateEntries`, `evts`, `src`, `tags`, `result`, `data` | all | become local `let/const` (strict mode in modules would throw otherwise). Not observable: nobody reads them (grep) |

Replacing alert/console by a returned `warnings[]` ([SEAM-702](../intent/seams.md)) is a semantic
change: a later step, not this slice.

During the move (steps 1-3) known defects stay as they are and are pinned by the golden tests as
current behavior (DEC-004): [DEBT-710](../intent/debt.md) (dead `"array"` branch, `null`/primitives
throw), DEBT-712 (globals, declared only as far as strict mode needs), DEBT-726 (three near-identical
CSV converters, kept), DEBT-734 (v2 without `data` gives an empty model). Other strict-mode
differences found by the goldens are recorded as DEBT and kept equivalent.

The maintainer also wants obvious bugs fixed in this slice (section 5). They are done afterwards,
as separate semantic commits (step 4), never inside the move.

## 3. Steps (separate commits, page working after each)

1. **Harness + goldens, no production change.** Under `refactor/tests/` only (Q11): a Node runner
   with no npm dependency, synthetic fixtures (Q8), and goldens generated by evaluating the
   OLD functions out of `AnnotationIO.js` in a `vm` context with stubbed globals. Cases: v1 object,
   v1 array, v1 bad key, `null`/number input, v2 plain, v2 duplicate ids (alert recorded),
   v2 wrong `info.type`, v2 with `ID` and `labels` aliases, v2 without `data`; one CSV per converter
   incl. missing tag ids and invisible parts; DB result with two frames; `tagsAddFrames` with null holes.
2. **Add** `labelbee/static/labelbee/js/annotation/AnnotationCodec.js` (ES module, named exports,
   `deps` parameter, legacy function names kept) in `js/annotation/`. A small bridge script
   (`<script type="module">` in `labelbee_page.html`) imports it and assigns `window.<name>` wrappers that
   pass `{hasLabel, alert, log, logIO}`. The module itself never touches `window`. Goldens must pass.
3. **Redirect + delete**: remove the old definitions from `AnnotationIO.js`; the existing in-file
   calls now resolve to the bridge. Check that the module is loaded before the first user action
   (module scripts are deferred, classic ones are not; no call happens at load, to be confirmed).
4. **Fix bugs (semantic, one commit each, goldens updated explicitly)**, only clear-cut candidates the
   maintainer signs off one by one: DEBT-710 (`typeof obj == "array"`, `&` for `&&` in the key check),
   `setTags` validating the global `Tags` instead of `obj` (in `setTags`, so only once it is in scope),
   and any found by the goldens. Each updated golden shows the intended behavior change.
5. **Record**: PLAN, and the intent entries touched (SEAM-702 code list, BEH-717/735 `Code:` paths).

Bridge entries stay until slice 2 moves their callers (the loaders); they are listed in the PLAN.

## 4. Checks

- Automated: the goldens of step 1, run on old code (generation) and new code (verification).
- Manual, in the browser, by the maintainer (needs a server): load a v1 and a v2 events file; load a
  file with duplicate ids (alert appears); load tracks CSV, tracks_tagged CSV and tags CSV from the
  server dialog; load a tags JSON; DB source if available. These become `tests/CHECKLIST.md` items.

## 5. Maintainer decisions (2026-10-30)

- Test runner: Node made available to the sandbox ([Q15](../QUESTIONS.md#q15)); step 1 waits for it.
- `hasLabel`: injected through `deps`; label helpers stay in `SelectionControl.js`.
- Goldens: generated by running the OLD code in `vm`.
- Cut: all pure load functions of section 1 (JSON, CSV and DB helpers).
- Location `js/annotation/AnnotationCodec.js`; files are PascalCase named after the module; exports keep
  the legacy function names (renaming is a later step); folder per capability group.
- Warnings: `alert`/`console` injected through `deps`, same text and moment.
- Bridge: wrapper script sets `window.*`; the module does not touch `window`.
- Tests pin return values, the alert (text and count) and error-path logs (`console.error`,
  "ABORTED"/"unsupported" messages); routine progress logs are not pinned.
- Bugs: only clear-cut ones (no plausible reading makes the code correct) are fixed in this slice;
  ambiguous cases stay `DEBT`. Done as separate commits after the move (step 4), each approved
  individually. CLAUDE.md "Rules" amended accordingly (general exception, not slice-specific).

  the call sites of `sanitizeEvents`; the helpers themselves are not tested.
