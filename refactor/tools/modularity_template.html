LabelBee modularity map

One box per class, one per classic script (all its globals and global functions) or ES module. Big files are split into sub-blocks by concern. Facts come from a static scan of __NUNITS__ functions and variables (refactor/tools/modularity_scan.js, modularity_build.js).

read-only read, or a getter that writes nothing write / input command, setter, signal slot ⚡ read / write written from outside red: global variables of another box, and calls / calledBy not drawn namen: n boxes use it from outside

Members used by no other box are internal. A chip is classified from how other boxes use it: fields and variables written elsewhere are read / write, functions that write state or fill signals are write / input, getters and value-returning functions are read-only. Edges: solid = calls, dashed = reads or writes of data; hover a block to light its edges red. Calls to other tabs are listed in red inside each block.
